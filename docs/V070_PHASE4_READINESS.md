# Phase 4 Readiness (Market Analysis Monitor)

## Что готово
- `RegimeService.analyze(symbol, as_of, base, tfs)` → объяснимый `RegimeSnapshot` с BTC context и MTF.
- Историю под анализ загружает `regime snapshot --refresh` (ровно `bars_per_value` баров на каждый таймфрейм).
- Snapshots сохраняются идемпотентно, их историю можно смотреть через `regime history`.

## Что нужно решить в спецификации Phase 4
1. **Цикл монитора.** На каждом закрытии бара базового таймфрейма: догрузить последний закрытый бар → проверить отсутствие STALE → посчитать режим → сохранить. Без догрузки получится массовый UNKNOWN(STALE).
2. **Источник данных.** Bybit Demo trading использует mainnet market data. Market data layer уже берёт данные с mainnet public API, отдельный «demo market data» endpoint не нужен.
3. **Задержка закрытия бара.** Бар доступен через REST не мгновенно после закрытия. Нужна пауза и/или повторная попытка, иначе первый опрос будет STALE.
4. **Hysteresis режимов.** Решить, нужна ли минимальная длительность режима до смены (по истории snapshots). Это будет regime v2 с новой `REGIME_VERSION`.
5. **Нагрузка.** Прогрев 800 баров × 3 таймфрейма × N символов при старте; далее по 1 бару. Проверить время расчёта (сейчас O(окно) на точку).

## Вердикт
**READY** для Phase 4 при условии, что пункты 1 и 3 будут зафиксированы в её спецификации.
