# QRE v0.7.0 — Feature Methodology

## Численная точность
- Входные данные — `Decimal` (точные значения биржи). Конвертация в IEEE-754 double происходит **один раз** в `ValidatedSeries` (`float(Decimal)` — корректно округлённое преобразование).
- Features — статистики, поэтому считаются во `float`. Суммы — через `math.fsum` (компенсированное суммирование).
- Деньги (PnL, комиссии, funding) остаются `Decimal` в accounting и через feature engine не проходят.
- Артефакты двоичного представления (например, `hl_range = 61.76000000000204`) ожидаемы. Сравнивать значения нужно с допуском; детерминизм при этом побитовый (тест сравнивает `float.hex()`).
- NaN/±inf никогда не становятся VALUE.

## Критерий warmup (один на все рекурсивные фильтры)
Рекурсивный фильтр `s_t = α·x_t + (1−α)·s_{t−1}`, засеянный SMA первых N баров. Через k шагов вес seed = (1−α)^k. Требуем (1−α)^k ≤ e⁻⁶ ≈ 0.248 %:

`k = ceil(6 / −ln(1−α))`

| Фильтр | α | k (warmup) | min_observations |
|---|---|---|---|
| EMA-20 | 2/21 | 60 | 20 + 60 = 80 |
| EMA-50 | 2/51 | 150 | 50 + 150 = 200 |
| EMA-200 | 2/201 | 600 | 200 + 600 = 800 |
| Wilder ATR-14 | 1/14 | 81 | 1 + 14 + 81 = 96 |

Рекурсивная часть EMA-200 — 600 баров (требование Phase 1 «≥ 600» выполнено), полное окно одного значения — 800. Единственный источник истины для длины истории — `FeatureSpec.min_observations`: ingestion получает его через `FeatureService.bars_per_value(names)` и передаёт в `plan_history / ensure_history(bars_per_value=…)`. Для N полезных точек нужно `N + bars_per_value − 1` баров (тест `test_planned_history_is_enough_for_every_usable_point`).

## EMA
- **Seed:** SMA первых N значений окна.
- **Рекурсия:** `e_t = α·C_t + (1−α)·e_{t−1}`, α = 2/(N+1).
- **Окно:** ровно `N + warmup` последних непрерывных закрытых баров («windowed EMA»). Значение зависит только от окна, а не от того, сколько истории загружено. Поэтому оно детерминировано и воспроизводимо в бэктесте (тест `test_independent_of_loaded_history_length`).
- **Отличие от «бесконечной» EMA** (TradingView, биржа): расхождение ограничено весом отброшенной истории ≤ 0.25 %. Сверять нужно с допуском.
- **Пропуски:** gap-strict. Дыра в окне → DATA_QUALITY_FAILURE до восстановления.
- **Свечи:** только закрытые.
- **Производные:** `dist_ema_N_pct = C/EMA − 1`; `ema_N_slope_k = EMA_t / EMA_{t−k} − 1`, где оба значения посчитаны на своих точных окнах (поэтому совпадают с `ema_N` в соответствующие моменты); `ema_50_200_spread = EMA50/EMA200 − 1`.

## ATR (Wilder)
`TR_t = max(H−L, |H−C_{t−1}|, |L−C_{t−1}|)`; seed = среднее первых 14 TR; `ATR_t = (ATR_{t−1}·13 + TR_t)/14`. Окно 96 баров. `atr_14_pct = ATR/C`.
**Никакого fallback:** при нехватке данных ATR = INSUFFICIENT_HISTORY или DATA_QUALITY_FAILURE с причиной. Константы вида 1.5 % в коде отсутствуют — это проверяет тест.

## Волатильность — четыре разные величины
| Feature | Что измеряет | Единица |
|---|---|---|
| `hl_range_pct` | размах одного бара | доля цены |
| `atr_14`, `atr_14_pct` | сглаженный размах с учётом гэпов | цена / доля |
| `ret_std_20` | выборочное std (ddof=1) 20 лог-доходностей | лог-доходность за бар |
| `realized_vol_20` | √Σr² (без вычитания среднего), не аннуализирована | лог-доходность за 20 баров |
| `vol_20_annualized` | `ret_std_20 · √(bars/год)`, год = 365 дней (крипта 24/7) | годовая |
| `vol_ratio_20_100` | std20/std100 — нормализованная волатильность | безразмерная |

## Доходности
`ret_cc = C_t/C_{t−1} − 1`; `log_ret = ln(C_t/C_{t−1})`; `ret_oc = C_t/O_t − 1`; `ret_20 = C_t/C_{t−20} − 1`; `hl_range = H−L`; `true_range` — как в ATR. Доходность через дыру не считается.

## Объём
`volume` — base coin, `turnover` — quote (единицы из Phase 1). `rel_volume_20 = V_t / mean(V_{t−20..t−1})` — текущий бар исключён из базы. Нулевая база → NOT_AVAILABLE. `vt_anomaly_count_20` — число баров, где turnover/volume вне [L, H] ± 0.5 % (тот же допуск, что в ingestion).

## CVD
**True CVD = NOT_IMPLEMENTED.** Для него нужна разбивка сделок по стороне тейкера; OHLCV её не содержит. Feature `cvd` всегда возвращает NOT_AVAILABLE с причиной.
Вместо него есть `clv_volume_pressure_proxy_20` = Σ(V·CLV)/ΣV, где CLV = ((C−L)−(H−C))/(H−L). Он явно помечен `is_proxy=True, proxy_for="cvd"`. Тест запрещает любому реализованному feature упоминать CVD, если он не помечен как proxy.

## Структура / ликвидность (proxy, не SMC)
`rolling_high/low_20` — экстремумы **предыдущих** 20 баров, текущий бар исключён (иначе «пробой» был бы невозможен по определению). `dist_high/low_20_pct`, `range_position_20` (вне [0,1] = выход из диапазона), `volume_concentration_20 = max V / Σ V`, `amihud_20 = mean(|r|/turnover)·10⁶`.

## Look-ahead
Гарантируется конструкцией, а не дисциплиной авторов формул: фильтр `close_time ≤ as_of` применяется до построения окна, а формула видит только окно. Тесты: добавление будущих баров, «отравление» будущих баров абсурдными значениями, контрольный тест (изменение бара решения *меняет* значение, то есть тест не вакуумный), эквивалентность исторического калькулятора и точечного расчёта, проверка, что формула получает ровно `min_observations` баров.

## Retrospective analytics
Сейчас не существует. Если появится (например, «максимум за следующие N баров» как метка для обучения), она должна жить вне реестра trading features и никогда не попадать в `FeatureSnapshot`.
